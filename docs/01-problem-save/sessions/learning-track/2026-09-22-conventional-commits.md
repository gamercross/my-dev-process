주제: Conventional Commits
왜 배우는가(동기): 이 저장소의 커밋 메시지 형식이 지금까지 느슨하게 관행적으로만
맞춰져 있어서, 나중에 커밋 이력만 보고 변경 종류(기능/버그수정/문서)를 자동으로
구분하기 어렵다.
학습 자료(출처): https://www.conventionalcommits.org/en/v1.0.0/
핵심 개념 요약(Feynman 기법 — 전문 용어 없이 내 언어로 설명): 커밋 메시지 첫 줄을
"타입(범위): 요약" 형태로 고정한다(feat/fix/docs/refactor/test/chore 등). 사람이
아니라 기계가 커밋 이력만 읽어도 "이건 기능 추가, 이건 버그 수정"을 구분할 수
있게 하는 게 목적이고, 여기서 더 나아가면 feat=minor, fix=patch, "BREAKING
CHANGE"=major로 버전을 자동 계산하는 데까지 쓰인다(SemVer와 연결).
막힌 부분/질문(있다면): 이 저장소가 지금까지 써온 "feat: ...", "docs: ..." 형식이
이미 이 규격과 거의 같다는 걸 확인 — 완전히 새로 배운 개념이라기보다는 이미
하던 관행에 이름과 근거가 붙은 경우였다.
완료 기준(무엇을 할 수 있으면 끝났다고 볼 것인가): 커밋 메시지 첫 줄만 보고
그게 기능/버그수정/문서 중 뭔지 맞힐 수 있으면 끝.
상태(학습중 / 이해완료 / 적용해봄): 이해완료

## 7단계: 유지보수 (짧은 회고, Lite 등급이라 배운 게 있을 때만)

이 저장소가 이미 관행적으로 "feat: ...", "docs: ..." 형식을 써왔다는 걸
확인한 게 배운 점이다 — 새 규칙을 도입한다기보다, 이미 하던 걸 표준(Conventional
Commits)에 이름 붙여 확인한 셈. 새로 배운 패턴/체크리스트 항목은 없음(이 학습
자체가 이 워크플로우 시스템의 "패턴/체크리스트"에 해당하는 산출물이 아니라,
이미 하던 습관을 표준과 대조해 확인한 것이라 카탈로그에 추가할 게 없음).
