# 분석 체크리스트

7단계(유지보수)에서 놓쳤던 요구사항 유형이 쌓이는 곳. 2단계(문제 분석)에서 매번 이 목록을
확인합니다.

## 기본 체크리스트 (IEEE 830 기반 시작점)

- [ ] 각 요구사항 문장에 동작이 하나만 담겨 있는가?
- [ ] 정성적 표현("빠르다", "편하다") 대신 측정 가능한 기준으로 썼는가?
- [ ] 엣지 케이스(빈 입력, 최대/최소 경계값, 동시성)를 나열했는가?

## 2단계 파이프라인 체크리스트 (docs/02-problem-analysis 참조)

- [ ] 기능 요구사항이 EARS 5가지 문형(Ubiquitous/Event-driven/State-driven/Unwanted/
      Optional) 중 하나로 작성됐는가?
- [ ] 비기능 요구사항마다 Planguage의 Scale/Meter/Goal이 채워졌는가?
- [ ] 요구사항마다 MoSCoW와 Kano 분류가 둘 다 되어 있는가?
- [ ] 요구사항이 5개 이상이면 RTM(추적 매트릭스)이 작성됐는가?

## 3단계 파이프라인 체크리스트 (docs/03-pattern-analysis 참조)

- [ ] 후보를 표준 카탈로그(알고리즘 4대 패러다임 / 아키텍처 5대 스타일)에서 먼저 찾아봤는가,
      아니면 감으로 골랐는가?
- [ ] 후보가 2개 이상인데 ATAM 비교표 없이 넘어가지 않았는가?
- [ ] 프로젝트 트랙 결정이면 ADR로 남겼는가? (번호/상태/불변성 규칙 준수)
- [ ] 선택 근거(왜 이걸 골랐는지) 한 줄이 남아 있는가?
